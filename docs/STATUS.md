The plan for Fuobe Originals (open-weight versions of Higgsfield's own products) is in [`higgsfield-originals-5.md`](research/higgsfield-originals-5.md) and [`fuobe-originals-recipes-5.md`](research/fuobe-originals-recipes-5.md); Genjutsu's Character swap and the Character Swap Studio follow [`openjutsu-6.md`](research/openjutsu-6.md) (Comfy Org's Openjutsu and Akatz Labs' H3 Character Swap). Round 5's research: [`new-models-7.md`](research/new-models-7.md) (Open-H3-Regenerate-2K, WorldCast, MOSS-Image Layout), [`dbs-separation-7.md`](research/dbs-separation-7.md) (DBS soundtrack separation), [`work2skill-7.md`](research/work2skill-7.md) (skills that run by themselves) and [`accounts-8.md`](research/accounts-8.md) (accounts in three modes, now background only); round 5, part 2 adds [`idol-9.md`](research/idol-9.md) (Idol, one picture to a 3D splat: a plan of 9 packages). Since round 4, part 5 (O7), Fuobe calls no Higgsfield model or API: Higgsfield is only what Fuobe is measured against. Since the owner's decision of 2026-10-29, a feature gets a cloud route only when its model (or a base model that takes LoRAs) is hosted on fal or Replicate; otherwise it runs on the open engine only, with no stand-in recipe in the cloud. Since 2026-10-30 each engine does all it can: the open engine keeps every capability it has (LoRAs, custom nodes, longer clips, references) even where the cloud can't match it. Accounts are the owner's public sign-up on `main` ([`public-signup.md`](public-signup.md)): guests browse, and accounts see a guest view of the owner's library and run only on their own ComfyUI. What is queued next, in what order, and what waits on the owner is in [`HANDOFF.md`](HANDOFF.md)._

**Library, data and security**
- "Move to" and "new folder" in the Library's selection bar still act on the whole selection, including results hidden by a search or filter; the count and the other actions follow the shown results.
- Without Web Locks (plain `http://` on a LAN IP) each visible tab reads its own live stream; six or more visible windows on one host could hit the browser's connection limit.
- **Sign-in is off by default.** Without a password Fuobe answers only on local addresses and names in `FUOBE_ALLOWED_ORIGINS`, but anyone who can reach it can use it (and your keys). With a password, a page that rebinds DNS can still post password guesses; the throttle caps that at roughly 15–20 a minute. Without `FUOBE_TRUST_PROXY=1` behind a reverse proxy, all visitors share one throttle (slowed, never locked out). `comfyLorasDir` (now also where LoRAs are downloaded) and `aiToolkitDatasetDir` make the server write files where you point them. Save & test lets a signed-in caller make the server fetch a ComfyUI or local LLM server address without saving it (saving it already allowed the same). Share links skip sign-in by design (next bullet).
- **Share links are public.** GET and HEAD on `/s/<token>` and its files pass without a session, even with a password set, after the host allowlist and the cross-site check. Set `FUOBE_PASSWORD` so the rest of the studio stays locked (the Share dialog warns if not): on a password-less install an outside visitor can open a link only if the host is in `FUOBE_ALLOWED_ORIGINS`, which opens the whole studio too. Only a SHA-256 of each token is stored. Wrong tokens get 404, and 429 past 100 a minute; behind a reverse proxy, `FUOBE_TRUST_PROXY=1` lets Fuobe lock out the client that guesses, and without it no one is locked out. The files route serves only what the share page shows, and blanks generation data with a hand-written cleaner (`src/server/media-clean.ts`): a bug there would leak metadata or hide a file.
- **Models & licences has no admin role:** anyone who can sign in, or holds an API token, can change the switches (`PUT /api/settings/models`); with no password, anyone who can reach the install.
- Assist connector tokens and URLs are stored in plain text in SQLite, like the other keys, and masked before they reach the browser.
- **LoRA downloads through the API:** anyone with a Fuobe API token can name a LoRA link in `POST /api/generations` (at most 8; only links on huggingface.co, hf.co, civitai.com, fal.media and replicate.delivery) and make the server download it into the LoRA folder. Links on hf.co, fal.media and replicate.delivery aren't fingerprint-checked and have no size limit (60-minute timeout).
- **Canvas data format:** a canvas is saved as pages (`{pages:[…]}`) the next time it is saved, and older Fuobe builds can't read it after that; back up the data folder before trying this version if you might go back. Scripts that read `canvas.graph` from `GET /api/canvases/:id` must read `canvas.pages` now. No database migration was needed.
- **Migrations 21 and 22** (round 4, part 5) run on their own at the first start. 21 adds the Character Swap Studio's `swap_projects` table. 22 deletes the saved Higgsfield key, turns "Higgsfield first" into Automatic and marks Higgsfield ads `baked`; it can't be undone, so back up the data folder (or `FUOBE_DATA_DIR`) before upgrading if you might roll back.
- **A data folder that ran the old PR #15 branch** (`claude/fuobe-parity-4` up to f7c6d8e, or `claude/fuobe-r5-batch-7` up to c9cd489) has places 23 and 24 of the migration list marked done for the dropped acc-1 and acc-2 (identity tables and an audit-log trigger); on `main` those places are the GPU pre-flight's tables and `assets.account_id`. Since round 5, part 2 the first start repairs such a folder: it forgets either place when main's work is missing and the dropped package's is there, so main's migration runs (`tests/dropped-branch-migrations.test.ts`). Back it up first. The old accounts tables, `data/secret.key` and `data/backups/` stay, unused; sign-in goes back to `data/auth.json`, so a password or token changed on that branch is lost, and that branch's `FUOBE_MODE`, `FUOBE_SIGNIN`, `FUOBE_SECRET`, `FUOBE_OWNER_PASSWORD` and `FUOBE_TRUSTED_PROXIES` are ignored (`main` reads `FUOBE_PASSWORD` and `FUOBE_TRUST_PROXY`). A folder that only ever ran `main` is left alone. PR #15 adds no migration.
- **Public sign-up and round 5, part 2's tools:** no browser check runs as a guest or an account (`tests/public-signup-tools.test.ts` covers the API answers). Accounts with a GPU see the new `/connect` rows and a price for Split soundtrack and Turnaround, then are told the tool doesn't run on their own GPU yet. Each Split price check calls their ComfyUI (again each time it doesn't answer) and, like main's Loop / extend and Join, reveals whether a file link the visitor has exists, with its length and channels.
- **Fuobe Soul's finish route** (`POST /api/generations/[id]/finish`) takes the PNG the browser made and puts it in place of the output; the raw picture stays as `meta.original`, the first upload wins, and the route is guarded only by the app's usual sign-in.
- `MAX_INLINE_TEXT` caps a result's inline text at 64,000 characters; `meta.cues` of a very long transcript stays inline.

The `fuobe` CLI is covered by `pnpm test`; to use it against a running server, see [`docs/cli.md`](cli.md) (`npm link`, or `node bin/fuobe.mjs …`).

`node scripts/gen-demo-3d.mjs` regenerates the demo GLB and turntable (needs ffmpeg); `pnpm gen:catalog` regenerates the catalog from `docs/research/*.json`, now including the LoRA library, the AI Influencer options, Fuobe Soul's looks (`scripts/gen-soul-originals.py`), Soul ID's trainers (`scripts/gen-trainers.py`) and, since round 4, part 5, the Photodump packs and Fashion templates (`scripts/gen-studio-packs.py`, in place of the two Higgsfield generators). `python3 scripts/fetch-hosted-schemas.py --partner` refreshes the partner routes in `docs/research/fuobe-originals-recipes-5.json` (fal's Happy Horse 1.1). Licences are information: the LoRA and Soul generators print licence notes instead of stopping; they still stop on a data error (pins, SHA-256, names), and the Soul one on a look with more than three LoRAs.
