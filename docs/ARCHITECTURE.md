# Architecture

Fuobe is a single Next.js 16 app. The browser (and the `fuobe` command line) talks only to Fuobe's own API; the server talks to providers (fal.ai, Replicate, Higgsfield, ComfyUI, and Claude or Ollama for text), fetches LoRA files from Hugging Face and civitai when a run needs them, and stores every input and output locally, so the library never depends on a provider's expiring URLs.

```
            proxy.ts: hostAllowed() (no password set) → crossSite() → sign-in (session cookie or API token)
                      → a real 404 for an unknown app, hub mode or record id (src/server/records.ts)
                                              │
Composer / studio (React) ──POST /api/generations (or a studio route that builds a pipeline)
                                              │

                                              ▼

                                              │  NEEDS / requires / minImages: says which input is missing

                                         engine mode check        Settings → Engine mode (both / open / cloud)
                                         chooseRoute()            first configured provider for that operation, preferring one that carries
                                              │                   every LoRA and makes the clip length asked (Preferred provider sets
                                              │                   fal/Replicate order otherwise; "llm" for text steps), else the demo
                                              │                   provider (Settings → Demo mode)

                                              ▼

                                              │  SQLite row (queued) → submit() in the background
                                              │  (a row with depends_on waits until every generation it names succeeds,
                                              │   then gets their outputs through its chain slots: see Pipelines)
                                              │  upload inputs to the provider (prepareFile), optional prompt enhancement,
                                              │  LoRA files: downloaded into ComfyUI's folder, or mirrored to fal / Replicate (src/server/loras.ts),
                                              │  adapter.submit() → external job id (generation_runs.submitted_at)
                                              ▼
       runner (started at boot by src/instrumentation.ts; every 1.5 s, plus a 500 ms lane for jobs near the end)
```

A **model** has one **route** per (operation, provider). A route's `FieldMap` translates Fuobe's canonical input (`prompt`, `images`, `image2`, `endImage`, `video`, `videos`, `audio`, `audios`, `aspectRatio`, `duration`, `voice`, `voiceAudio`, `dialogue`, `shots`, `draft`, `startTime` / `endTime`, `fps`, `palette`, `styleId`, `numLayers`, `sourceLanguage`, `targetLanguage`…) to the provider's field names. Dotted keys (`voice_settings.stability`) are written as nested objects; `setPath` ignores `__proto__`, `constructor` and `prototype`. `defaults` are sent unless the request sets them (applied before the canonical fields), `fixed` always wins (applied after). `sourceLanguage` may be `{key, values}`, matched to the API's list. `palette {key, format, background}` converts hex colours to each API's shape (Recraft on fal, Recraft on Higgsfield, Ideogram members with falling weights, plain lists). `tracks` and `timeline` build fal FFmpeg compose timelines. Masks are converted to each API's convention (white = change, black = change, or alpha) by a small PNG codec (`src/server/png.ts`).

Round 4 adds 17 operations (`remove-object`, `video-swap`, `video-insert`, `keyframes`, `sdr-to-hdr`, `export-video`, `ocr`, `still-motion`, `audio-loop`, `audio-join`, `scene-3d`, `splat`, `text-to-3d`, `rig-3d`, `extract-frames`, `images-to-video`, `overlay`) with labels, output kinds and NEEDS, and the canonical params they use: `points` (clicked on the first frame), `keyframeTimes`, `format` (a `VideoFormat`: H.264, 10-bit H.265, ProRes 422 HQ or 4444, FFV1, EXR, and on the open engine HLG or PQ 10-bit), Ken Burns `zoomFrom` / `zoomTo` / `panFrom` / `panTo` / `easing`, `crossfade`, `sourceDuration`, `frameInterval`, `targetFps`, `slowdown`, `colormap`, `sideBySide`, `matteOutput`, `position`, `scale`, `animation`, and `inputs.model3d`. `FieldMap` gains a key for each (`points` in Bria's or SAM's shape, `keyframes` as image + frame index at the API's fps, `zoom` for fal's zoompan, `loop` by repetition, `numFrames` from the clip's length, `upscaleFactor` from the target size and the clip's shorter edge…), plus `ranges` (clamped and rounded before sending), `maxImages`, `omitEmptyPrompt` and `ignore`. `EnumField.accepts` sends the closest value an API takes when a model runs on two APIs (Grok Imagine on fal and Higgsfield). `GenInput.sourceSize` and `sourceFps` (and `sourceDuration`, unless the request set it) are filled on the server from the input clip's header (`src/server/media-facts.ts`: MP4 / MOV, then WebM / Matroska).

`ModelOptions` describe what the composer shows: aspect ratios, resolutions, durations, audio, end frame, multi-shot, draft mode, voices and voice cloning, languages, sliders, enum controls, provider-fetched preset lists, motion paths, and since round 3 `minImages` + `imageLabels` (try-on: "Person photo", "Add garment"), `promptless`, `maxVideos` / `maxAudios` (reference clips), `sourceLanguages` and `requires` ({images?, prompt?, msg}, checked in `planGeneration` before any job is created). `Pricing` gains `byResolution` (a price per `params.resolution`) and `inputSeconds` (per-second prices doubled for edits billed on input + output). Round 4 adds `promptOptional` (the box shows, but the model also runs without words), `requires.mask` / `points` (video erasers), `formats`, `colormaps`, `sideBySide`, `matteOutputs`, `keepsNamed`, `fpsTargets`, `slowdowns` and `labels` on controls; `ModelDef.worker: "isolated"`; `ModelRoute.chained` (a route the server builds as several jobs: the open keyframe film) and `ModelRoute.preview` (the parts of the map the composer previews a result with, kept in the slim client catalog). `Pricing` gains `promo` (a launch price to a date: FLUX 3 Max at 720p is $0.0425/s until 2026-11-07, then $0.17/s) and `factors` (multipliers by a setting: Topaz 60 fps ×2, ByteDance Pro ×10, FLUX.3 Creative about ×1.4).

`plan.ts` adds `promptOptional(model, op)` (promptless ops such as trim, mux, captions, layers, image-to-3d, vectorize), NEEDS entries with `oneOf` and `media` (transcribe and separate-audio take audio or video), a server-only check that rejects inputs no route can send (it needs the field maps the slim client catalog strips), and `inferOperation` picking `ref2v` when clips are attached. Since round 4, two or more images are `keyframes` when they carry `keyframeTimes` (or the model has no `ref2v` and no chained route), checked by `checkKeyframes` (on a chained route: up to 10, the first at 0 s, every gap within the model's clip lengths); a `format` the model doesn't write is refused; `checkVideoToolOptions` refuses colour maps and matte outputs the model can't make, and Remove background fills `params.matteOutput` with the model's first; a remove-object request can name its target with a mask or points instead of words when a route reads them (`markedTarget`). `estimateCost(model, params, jobs, op)` prices upscale-video, interpolate, sdr-to-hdr and export-video by the clip's seconds (`params.sourceDuration`; slow motion by the stretched length) and applies `Pricing.factors`. `chooseRoute` (in `src/server/generations.ts`) passes over a route whose image list takes fewer images than the run sends (`FieldMap.maxImages`).

Round 4 part 2 makes LoRAs part of any run (see LoRAs). `FieldMap.loras` is a `LoraField` in one of four shapes: `items` (fal's `loras: [{path, scale, transformer?, weight_name?}]`, with a maximum, a scale range and whether the API refuses an empty list), `arrays` (Replicate's `lora_weights[]` + `lora_scales[]`), `experts` (one LoRA per Wan 2.2 expert, Replicate's Wan 2.2 fast) and `single` (one URL and one scale field). `FieldMap.size` writes width and height from the aspect ratio on a base×base pixel budget (Replicate's Z-Image LoRA model), and `numFrames` gains `step` (Wan 4n+1, LTX 8n+1 frames) and `fromDuration` (extend: the frames to add, at the clip's own frame rate when known). `ModelRoute.loraEndpoint` is now called whenever a run carries LoRAs, not only for a trained identity, and `Pricing.withLoras` is its price. `LoraRef` gains `weightName`, `hostedUrl` (a mirror), `version` (a civitai version id or a Hugging Face commit) and `licence` (`LoraLicence`: commercial, hostedOk, the snapshot date, civitai's permissions). In `plan.ts`, `planGeneration` puts the request's own LoRAs (an @character's trained identity) before a preset's and a Mix's, so on an API that takes few the identity wins, and leaves out a LoRA at strength 0 together with its trigger word at the start of the prompt; `routeLoras(route, loras)` says which LoRAs a route applies and why each other one is dropped; `estimateCost(…, withLoras)` uses the LoRA endpoint's price (the server's estimate does; the composer's own price doesn't yet); and a concat of one clip plus an appended still counts as two clips (an ad and its end card). `chooseRoute(candidates, images, loras, seconds)` now prefers a ready route that carries every LoRA and makes the clip length asked, then one that carries the LoRAs, then one that makes the length, then the first ready one, so a LoRA or length fit wins over Preferred provider. `prepare()` then fits the LoRAs to the route (`fitLoras`) and adds a note when a frame-count API can't make the length asked (`framedLength`: Replicate's Wan 2.2 fast renders 81–121 frames). The notes come back on the created generations (`Generation.notes`) and in the answer of `POST /api/generations` (and its preview), and the composer shows them as a warning toast; they aren't stored.

Round-4 open models in `models.ts`: the erasers `oss-vace-remove`, `oss-vace-remove-painted` and `oss-void-remove`; `oss-vace-swap` and `oss-vace-insert`; `oss-rife` (now `interpolate-rife-fps`), `oss-seedvr2` and `oss-upscale-video-esrgan` (now the chunked graphs, by target size), `oss-sdr-to-hdr` and `oss-export-video`; `oss-scene-moge`; `oss-vtracer`; and the hidden helpers `oss-ken-burns`, `oss-join-encoded`, `oss-audio-loop` and `oss-audio-join`. Wan 2.2 14B and Wan 2.2 14B Lightning get a chained `keyframes` route (`KEYFRAME_FILM` on `wan22-flf2v-14b`). `oss-latentsync` and `oss-thinksound` are no longer hidden; they carry `worker: "isolated"`. Round 4 part 2 wires four library graphs: `oss-ocr-lines` (OvisOCR3 on `ocr-lines-qwen35`, Layers' open text detection) and the hidden helpers `oss-reference-brief` (Gemma 4 E4B on `reference-brief-gemma4`, Content Factory), `oss-append-endcard` (`video-append-endcard`) and `oss-still-to-clip` (`still-to-clip`) for the Click to Ad end card. The cloud lists gain Seedream 5.0 Flash (`seedream-5-flash`, Mixed Media's cheaper frame editor) and six hosted open-weight models with LoRA routes: `qwen-image-2512-cloud`, `qwen-image-edit-2511-cloud`, `flux-2-klein-4b-cloud`, `wan-2-2-a14b-image-cloud`, `wan-2-2-a14b-cloud` and `ltx-2-3-22b-cloud`; `z-image-turbo-cloud` gains a LoRA field on fal and a Replicate route that takes LoRAs.

A **preset** (app / motion / effect) has a `cloud` and an `open` route, each naming a model and operation, optional fixed params and LoRAs. Apps pin their model; motions and effects add their camera / effect prompt to whichever video model the user picks (LoRAs only apply to the preset's own open model). `PresetChoice.extra` lets an option set model `params.extra`.

## Providers (`src/server/providers/`)

Every adapter implements `isConfigured`, `prepareFile`, `submit` and `poll`, and optionally `cancel` and `test`. `RemoteOutput` carries optional `text` and `meta`. `prepareFile(data, type, name, route)` gets the route the file is for (ComfyUI sends an isolated-worker workflow's inputs to that worker). `test({ focus })` names the setting being checked, for a provider whose settings reach more than one server (the Anthropic key, the isolated worker's address).

- **fal** — queue API (`queue.fal.run/<endpoint>`); always uses the `status_url` / `response_url` returned at submit. Files go to fal storage via `@fal-ai/client`. The key test (15 s timeout) counts only 2xx, 400, 404 and 422 as "accepted"; a proxy or an outage (405, 407, 5xx) reads "Couldn't check the key". Since round 4 part 2, LoRAs go in the route's LoRA field (`routeLoraField`: one item per file, Wan 2.2's expert as `transformer`, `weight_name`, the scale clamped, at most the API's maximum) and the call switches to the route's `loraEndpoint` (`loraEndpointFor`; an endpoint that needs at least one LoRA is never called with none). `prepareFile` uploads a named `File`, so uploads keep their name and extension (a mirrored LoRA stays `.safetensors`).
- **replicate** — predictions API; small files as data URIs, larger via the Files API. Outputs are copied immediately (Replicate deletes them after an hour). Since round 4 part 2 it sends LoRAs (before, it ignored them): `lora_weights` / `lora_scales` arrays, one LoRA per Wan 2.2 expert, or one field, switching to the route's LoRA model when it has one (`loraEndpointFor`).
- **higgsfield** — `api.higgsfield.ai` with `Key id:secret` auth: submit with idempotency keys, poll `/requests/<id>/status` (only the documented result fields are read; extra files such as zip or fbx land in `meta.artifacts`, which the runner now copies into the Library), cancel, signed-URL uploads, live style / template lists, and Soul ID training. The key test counts 401 and 403 as rejected, 400 / 404 / 422 as accepted, anything else as "Couldn't check".
- **comfyui** — loads `workflows/comfyui/manifest.json`. `prepareWorkflow()` turns a `GenInput` into the prompt: canonical keys → bindings, uploads it makes itself (including media refs in `params.extra`), LoRA nodes after each diffusion-model loader, width / height from aspect ratio + tier, frame counts as `n·step+1`, the palette as a hex sentence plus a 512×512 swatch rendered on the server, `SLOT_RULES` (repeat, required, hints) per workflow, and graph rewrites for `expand: "captions"` (`expandCaptionWorkflow` in `src/lib/comfy.ts`) and `expand: "timeline"` (`expandTimelineWorkflow` in `src/lib/av/timeline.ts`). A left-out reference in a FLUX.2 ReferenceLatent chain is removed by `bypassReference()`. The second audio track is read from `inputs.audio2` (else `params.extra.audio2`); a mux with no background picks the one-track graph. `prepareFile` records each upload's header facts (`src/lib/media-probe.ts`: MP4 / MOV / M4A with rotation, WAV, FLAC, MP3) so the "auto" shape, trim checks, lip-sync frames, the mux bed length, caption windows and the Whisper RAM guard use them. Progress comes over the websocket (reset when the URL changes), results from `/history`; `collectOutputs()` maps them in manifest order (text with cues and language, `model3d`, stems with `meta.stem`, layers back to front with `meta.z / name / bbox`, roles, VHS meta-batch passes followed by their `fuobe/<generationId>` filename prefix). A 502 or a missing prompt is retried; a prompt fails only after it is missing three polls in a row. The first `isConfigured()` per URL waits for a real probe from a worker thread (`probeComfySync`, at most 1.5 s).

  Round 4:
  - **Isolated worker routing.** `workerFor(endpoint)` reads the manifest's `worker: "isolated"`; that workflow's uploads, prompt, progress socket (a second websocket), polls and cancels go to Settings → Isolated worker URL (`comfyIsolatedUrl`, `COMFYUI_ISOLATED_URL`) instead of the main ComfyUI. With no address, or a worker that doesn't answer, the job fails with a message naming the setting; the connection test reports the worker beside the main server.
  - **Per-request graph work** in `prepareWorkflow()`: EXR requests switch to their own graph (`exrWorkflow`); `videoFinishValues()` sets export formats, the HDR colour space, FPS Boost's multiplier and frame step (FrameInterpolate is bypassed when the multiplier is 1) and the size of each pass of a chunked graph (`framesPerPass`, about 1.5 GB of frames); Ken Burns zoom / pan / easing are bound; a graph with `limits.maxDurationSec` refuses longer jobs; a crossfade uploads a small fade-curve WAV (`fadeCurveWav`) and refuses clips too short for it (`crossfadeProblem`). Remove object turns the words into SAM 3.1's target (`targetPhrase`), fills the gap with a neutral scene prompt (`REMOVE_SCENE`) and keeps the painted graph's hand-off mask output only when `params.extra.handOffMask` asks; swap and insert take SAM's target from `maskPrompt` or the prompt (`swapTarget`) and refuse clicks. Depth maps bind `colormap` and `sideBySide`; Remove background deletes the save node not asked for (`matteOutput`). Graphs that hold a whole clip in memory are refused above half the server's RAM (`wholeClipProblem`; `comfyRam()` reads `/system_stats`).
  - **Graph rewrites** in `src/lib/comfy.ts`: `tagMetaBatch` gives every VideoHelperSuite batch manager a per-job tag, and `dropVhsAudio` removes the sound link from VHS video loaders when the clip header says it is silent (both for every workflow that has those nodes, old ones too). `expand: "videos"` and `expand: "audios"` rewrite a join for every clip in one prompt (`expandVideoJoinWorkflow`, `expandAudioJoinWorkflow` in `src/lib/av/joins.ts`).
  - **Results and cancel.** EXR frames (output role `frames`) are fetched one at a time into a stored zip in the scratch folder and ride on the preview clip as `meta.artifacts.exr` (`bundleFrames`). Cancel (`stopPrompts`) deletes every queued prompt carrying the job's filename prefix and interrupts the running one; a meta-batch job is swept again up to 5 times, 1 s apart (`sweepPasses`). Uploads of `.webm` and `.mkv` are probed too.
  - **Round 4 part 2.** A graph with no diffusion-model loader refuses LoRAs instead of dropping them (`canTakeLoras` in `src/lib/comfy.ts`), and a missing-LoRA error points at the LoRA's model card and at Settings → LoRAs. `comfyLoraFiles(route)` reads `GET /models/loras` from the server that runs the route, for the download before submit (see LoRAs). An OCR graph's `lines` output is read by `parseOcrLines` (`src/lib/ocr.ts`: code fences, `bbox_2d` / `text_content`, 0–1000 boxes, cut-off answers) into text, `meta.lines` and `meta.size` (from its `frame` output); an answer with no list keeps its words, with `meta.unreadable`. `video-append-endcard` is bound to the ad's own width, height and fps from its header (an unreadable header is refused), and a silent ad loses the LoadAudio chain that would read its sound (`dropLoadedSound`).
- **llm** — text steps in this process (below).
- **local** — results made in the browser (Color grading's PNG / WebM, Ads Studio composites; `/api/generations/local` records them).
- **mock** — demo outputs for every operation (SVG art, bundled sample clips, a tone, layers with meta, cue lists, two stems, a GLB with a turntable from `scripts/gen-demo-3d.mjs`), so the product works with zero setup. Round-4 operations answer too: a scene-3d job gets the GLB plus a grey depth PNG on the open engine and a Spectral-coloured depth PNG on the cloud, and an EXR job a sample clip with a zip that holds only a README. An extract-frames job returns as many frames as `max_frames` asks (4 without a count), so a per-frame Mixed Media demo fans out like the real one.

## Structured outputs

Outputs are not only media. `extractOutputs(response, op)` in `payload.ts` (fal, Replicate, Higgsfield) and `collectOutputs()` (ComfyUI) produce:

| kind / meta | from |
|---|---|
| `text` with `.text`, `meta.cues [{start, end, text, speaker}]`, `meta.language` | transcribe, translate, write; saved as `.srt` when timed, else `.txt` |
| `model3d` (GLB) with `meta.preview`, `meta.formats` | image-to-3d |
| layers with `meta {name, z, bbox, bboxNormalized, description}` | Seedream layers, Qwen-Image-Layered (bbox from alpha) |
| `meta.textBlocks`, `meta.textHtml` on the background | Ideogram text layers |
| `meta.stem` (`voice` / `background`, aliases vocals, accompaniment…) | separate-audio |
| `meta.styleId`, `meta.mask`, `meta.role`, `meta.artifacts` | Recraft styles, Bria cut-outs, ComfyUI roles, Higgsfield extra files |
| scene-3d: a GLB (`meta.role` `scene`) + a depth PNG (`depth`) on the open engine; a depth image (`meta.role` `depth`) on the cloud (`sceneOutputs`) | MoGe 2 (`scene-mesh-moge`), Marigold (`marigold-depth`) |
| `model3d` with `meta.format` (`ply` / `spz`) and `meta.preview` | splat |
| `model3d` with `meta.rigged`, `meta.animated`, `meta.formats` (fbx files, clips) | rig-3d |
| `text` with `meta.lines [{text, bbox}]`, `meta.size` (`meta.unreadable` when the answer has no list) | ocr: Florence-2 on fal; OvisOCR3 on ComfyUI (`ocrOutput`, round 4 part 2) |
| images with `meta.index` (source frame = index × frameInterval; a chain slot's `index` reads it) | extract-frames |
| a preview clip with `meta.artifacts.exr` (a zip of EXR frames) | sdr-to-hdr on LTX 2.3 HDR; open EXR export and HDR (`bundleFrames`) |
| `meta.role` `cutout` / `matte` (one kept, `keepMatte`) | Remove background (bg-remove-video) |
| `meta.role` `mask` (a window's last tracked mask) | the open painted eraser |

A media operation that only answers in words fails with "The model replied: …" (`noOutputsError`). `OutputFile.text` is inlined up to `MAX_INLINE_TEXT` (64,000 characters, `meta.truncated` beyond); chained steps read the full text from the file. `outputKind(op, model)` decides a generation's kind (color-match, timeline and scene-3d follow the model's kind: a 3D scene is a mesh on the open engine and an image on the cloud). Results without a prompt are titled after the operation ("Transcribe · ElevenLabs Scribe v2").

Files a result links to in `meta.artifacts` (LTX HDR's EXR zip, Higgsfield's fbx and zip) are copied into the Library when the job finishes (`persistArtifacts` in `generations.ts`): a link is streamed to the scratch folder by `fetchRemoteToFile` and moved into `files/outputs` (`adoptFile`); one that can't be fetched stays as it was.

## Pipelines and chained jobs (`src/server/chains.ts`)

A generation can depend on others (`CreateOptions.dependsOn`, one id or a list). `GenerationRequest.chain` (`ChainSlot[]`) says where each dependency's output goes:

| slot | what it fills |
|---|---|
| `images` (first / last), `endImage`, `video`, `videos`, `audio` | the matching input, from the dependency's first output of that kind (an `audio` slot fed by a clip takes its soundtrack) |
| `voiceAudio` | the voice to clone (tts) or the target voice (voice change) |
| `audio2` | the second track mixed under `inputs.audio` (mux): `inputs.audio2` / `GenInput.audio2` |
| `audios` | a list of clips (the spoken lines a voice timeline places at their start times; the clips of an audio join) |
| `model3d` | a 3D model (a mesh to rig) |
| `mask` | what to change (remove-object): the output marked `meta.role` `mask` (the open painted eraser's last tracked frame, handed to the next window), else a mask video (SAM 3.1's track), else a still |
| `prompt` | the dependency's text: replaces `{text}` in the prompt, or becomes it; a translate step gets the cue list (decided by the step's planned op) |

An audio slot can carry `stem` to take the output whose `meta.stem` matches ("voice" also matches vocals / speech / target; "background" also accompaniment / instrumental / residual / no_vocals). `pickOutput()` in `generations.ts` does the choosing; a missing stem fails the step with a clear message.

**`createPipeline(steps, opts)`** creates any DAG of steps `{key, request, after?, chain?}`. Before a single row exists it checks duplicate or unknown keys, self-waits, loops (Kahn sort, linear in steps + edges, since a per-frame render has hundreds), chain-slot counts and output numbers (`index` / `of`), that a step others depend on makes one job, and previews every step with placeholders; a mix of demo and real steps is refused (`assertOneMode`). Rows are created in topological order with `dependsOn`, labelled "Step n of N", and it returns `{batchId, items, byKey}`; if creation fails partway, what it started is canceled. Since round 4 part 2, `opts.existing` maps keys to generations made before (a retry's finished or running steps): new steps may wait for them, they aren't made again, and a demo step can't continue steps that ran for real. Its TSDoc example is a whole dub. Layers, Shorts, Mixed Media, the palette lock, Photodump / Fashion / Character Sheet, the AI Influencer builder's two-step sheet, Marketing Studio / Click to Ad / Ad Multiplier, dub, Katana, Remove object, Genjutsu, the Audio hub's Loop / extend and Join, and the Assist studio tools build their jobs this way; Cinema, Canvas, Faceless / Explainer, Content Factory's reading steps, Ads Studio and moodboards call `createGenerations` (with `dependsOn` for chained steps) directly; Cinema, Canvas and Faceless preview every step first.

At launch the runner fills the slots (`slotsFor` pads short chains, `chainValue` reads text files when the text isn't inline) and checks the mode again (`chainMode`: a real step after demo steps runs as a demo, or fails with what to connect when demo mode is off). Round 4 part 2 changes the runner for every chain, for per-frame work:

- **Fan-out and fan-in by output number.** `ChainSlot.index` takes the dependency's output number i of the slot's kind (by `meta.index` when the outputs carry it; past the end, the last one). One step per index fans a list out (a step per extracted frame); one step with a slot per index gathers it back in order. With `of`, the number of outputs planned, a list more than `CHAIN_LIST_SLACK` (2) short fails the step before it runs (`listShortfall`), so a frame or two lost at the clip's end is held, and half a clip of frozen, paid frames is not.
- **Waiting steps are picked by readiness.** `advanceDependents` reads `READY_DEPENDENTS` (`generations.ts`): waiting rows none of whose inputs is still queued or running, or one of whose inputs failed, was canceled or is gone. Before, it read the 50 oldest waiting rows, so a render with hundreds of waiting steps held up every chain started after it. A step whose input failed is now failed at once, even behind a backlog.
- **`dropWhenUnused`.** A waiting step marked so (today only per-frame Mixed Media's frame edits and clips) is canceled unpaid ("Stopped before it ran: the steps it was for failed", `DROPPED_UNUSED`) once every step that would use it has failed or been canceled. `dropUnused` runs when a chained step fails and on cancel, and walks up the chain.
- **Retries.** A launched step is stored with `chainFilled: true`; `unfilledRequest()` takes the chained inputs out again, so a retry can rebuild the step from new or kept dependencies (Mixed Media's `retryMixed`, with `createPipeline`'s `existing`).

Built on that:

- **Join clips** (`joinClips`): fal's FFmpeg `merge-videos` on the cloud, ComfyUI's `video-concat-{2,3,4}` on the open engine (folded four at a time). `oss-join-sound1/2` are joins that keep one clip's own sound at 25 fps (marketing films). `oss-join-encoded` (`video-concat-encoded`, `expand: "videos"`) joins up to 100 clips in one prompt by packet copy when they share size and frame rate; Faceless Frame by frame films use it, 24 clips per join.
- **Open multi-shot** (`createShotFilm`), **storyboard film** (`createStoryboardFilm`), **last-frame extend** (`createExtendChain`: extract frame → the model's image-to-video → join; `oss-extract-frame` on the open engine).
- **Keyframe film** (`createKeyframeFilm`): Frames mode on an open model whose `keyframes` route is `chained`. `createGenerations` hands a keyframes request on Wan 2.2 14B (or Lightning) to it: one `wan22-flf2v-14b` clip per pair of neighbouring frames, each as long as its gap in the workflow's frame steps (`planKeyframeClips`), then an image-to-video clip after the last frame when it isn't at the end, then a join. The whole request is previewed first, and clips already made are canceled when one fails. A chained route can't be a step that waits for another step's output: `createGenerations`, `previewChained` and Canvas's `describeNode` refuse it with one message (`chainedWaitMessage`).
- **Pieces and windows** (`src/lib/catalog/remove-object.ts`, shared by Remove object and Genjutsu): a long clip is cut into pieces each cloud model takes (`planCloudPieces`), or into frame-exact windows for the open graphs (`planWindows`, `planFrameCuts`; `VACE_WINDOW` is 4n+1 frames, up to 81). Each piece is trimmed and made, the pieces are joined, and the clip's own sound is put back (`joinWithSound`), with the helpers in `REMOVE_TOOLS` (fal trim / join / mux, or `oss-trim` / `oss-join-clips` / `oss-mux`). Open windows are joined with hard cuts; the seams have not been checked on real models.

## LoRAs (`src/lib/catalog/loras.ts`, `src/server/loras.ts`)

Round 4 part 2. A run's LoRAs come from a preset's open LoRAs (`oss-loras.generated.ts`), an @character's trained LoRA, or the request's `loras` (API callers and the evaluation harness: at most 8). The library (`lora-library.generated.ts`) gives each researched file its pins and licence; a LoRA the library doesn't know is the user's own. Nothing is committed to the repo: files are fetched when a run needs them.

- **Open engine.** Before a ComfyUI run, `ensureLorasOnComfy` compares the run's LoRAs with ComfyUI's own list (`comfyLoraFiles`) and the LoRA folder. A missing file is downloaded into Settings → LoRAs folder (`comfyLorasDir`, `COMFYUI_LORAS_DIR`) by `downloadLora`: a Hugging Face file at its pinned commit, a civitai file by its pinned version with the user's civitai key (`?token=`, redacted from error messages). The bytes are hashed while they stream to a `.part` file and kept only when they match the SHA256 pinned in the library (else the one Hugging Face or civitai states). One download per file runs at a time (`downloadOnce`), and the job's card shows its progress ("Downloading … · 40%"). With no folder set, the run stops with what to do; a gated Hugging Face file has to be placed by hand. `injectLoras` then adds the loader nodes.
- **Cloud engine.** `fitLoras` keeps what the route can carry: never a LoRA whose licence doesn't allow hosting (`localOnly`: the ref's or the library's licence says so), a gated Hugging Face file or a file that exists only on ComfyUI; over the API's maximum, the first ones win. Before submit, `prepareCloudLoras` gives each LoRA a URL the provider can fetch: a public file as it is; a civitai file is mirrored once to fal or Replicate storage through the adapter's `prepareFile`, only after civitai confirms that day that the model's permissions still include "Rent" (no answer, no copy). A mirror is made again after 7 days on fal and 1 day on Replicate (guesses: neither documents how long uploads live). The civitai key is never sent to fal or Replicate. Files downloaded only to mirror them live in `<data dir>/loras` (`LORA_CACHE_DIR`).
- **Records.** Every copy, a download into ComfyUI's folder or a mirror, is a `lora_mirrors` row (file, target, source URL, version, hosted URL, SHA256, size and the licence / permission snapshot it was made under).
- **Settings → LoRAs** (`src/components/lora-settings.tsx`) reads `GET /api/loras`: the library with each file's licence line, whether it is in the folder, where it was mirrored, a `folderProblem` for a folder setting that can't be read, and whether a civitai key is set (never the key). `POST /api/loras {file}` downloads one library LoRA now (`downloadToComfy`). The civitai key's Save & test asks civitai's `/me` (`testCivitaiKey`).
- **Research pins.** `scripts/fetch-lora-pins.py` pins every LoRA of the research to exact bytes (SHA256, size, the Hugging Face commit), and `scripts/fetch-hosted-schemas.py` reads the hosted endpoints' input schemas; both need the network and aren't part of `gen:catalog`. `gen-lora-library.py` fails on a missing pin or a licence-rule break (a non-commercial LoRA in a default row).

Checked: one pinned 85 MB Hugging Face LoRA was downloaded live through `/api/loras` and matched its hash, and the payloads are tested against the providers' schemas. No LoRA has run on fal, Replicate or a GPU, and civitai downloads and mirrors have never run live. A civitai LoRA sent to the cloud without a civitai key fails the run instead of being left out with a note.

## LLM provider (`src/server/providers/llm.ts`)

Text steps (`translate`, `write`) run inside the server and are polled like any job; cancel aborts the call and a restart fails the job as "Interrupted" (retryable). `llmBackends(route)` lists the backends in order: Claude (claude-opus-5-5, low effort, server-side fallback) when an Anthropic key is set and Prompt enhancement is Claude, or Auto on an install that isn't open-only; then Ollama when it answers, unless Prompt enhancement is pinned to Claude. Claude errors fall back to the next backend; endpoint `ollama` (`oss-text-llm`) never uses Claude; Prompt enhancement → Offline rewriter (`none`) turns text steps off. Since round 4 an open-source **translation** with no Ollama answering runs on ComfyUI instead, when ComfyUI answers: `viaComfy()` submits and polls the hidden `oss-qwen35-translate` model (Qwen3.5 4B, workflow `translate-qwen35-textgen`) with the same numbered batches, one prompt at a time, so cues keep their timing; writing still needs Ollama, and the message with neither running names both. The first check for a new Ollama URL is a blocking worker-thread probe (`probeOllama`), later checks refresh a 15 s cache in the background. A text step on Ollama costs 0. The connection test asks the servers themselves: the Anthropic key with a free one-model list call (`testClaude`), Ollama with `/api/tags` and whether the model Settings names is pulled (`testOllama`).

`translateCues()` translates JSON cue lists, SRT and WebVTT (`src/lib/cues.ts`) in numbered batches of 30 (multi-line cues kept together); a batch that comes back merged or short is redone in pieces of 10, then cue by cue through a pool (1 request in flight on Ollama, 4 on Claude). The output keeps `meta.cues`. `write` uses `params.extra.system` when given. Studios that need free text (brand research, the AI Director, storyboard splitting, ad copy, Click to Ad scripts, Content Factory's cloud style brief) call `llmText()` in `src/server/enhance.ts`, with offline fallbacks. Since round 4 part 2 `llmText` also takes pictures (Content Factory's reference frames: Claude image blocks, or `images` for an Ollama vision model; Content Factory asks again with words only when Ollama doesn't answer with the frames), and `llmTextBackend()` says which LLM would answer (Claude is the one that costs money). Faceless and Explainer names, topics and scripts, and Content Factory's episode titles, go through the llm provider itself (`askLlm()` in `src/server/faceless.ts` submits and polls a `text-llm` / `oss-text-llm` job), so they follow the episode's engine. The Explainer also reads PDF and Word sources (`POST /api/explainer/document`, up to 20 MB; `readDocument()` in `faceless.ts`): PDFs through Assist's unpdf reader, `.docx` through `src/server/assist/docx.ts` (`word/document.xml` via the bounded unzip, which skips entries it doesn't need); a document longer than the script writer reads is summarised by the engine's text model first. The file itself isn't kept.

## Live updates (`src/server/live.ts`, `src/lib/api.ts`)

Server: `watchGenerations(db)` installs TEMP SQLite triggers on `generations` that call a JS function (`fuobe_generation_changed`); changed ids are batched per event-loop turn (`setImmediate`) on an HMR-safe emitter (`globalThis.__fuobeLive`). The resolver in `generations.ts` turns each id into a `generation` event (the row through `toGeneration()`, the same JSON the list returns) or `deleted` (gone or trashed; trash and restore touch `updated_at`, so they fire too). `GET /api/generations/stream` (`generationEventStream`) sends `retry: 2000`, the events and `: ping` every 15 s, with `no-cache, no-transform` and `X-Accel-Buffering: no`; the listener is removed on abort.

Client: one stream per browser. Tabs elect a leader with `navigator.locks` (`fuobe-generation-stream`); only the leader reads the stream and re-broadcasts events and its connected state on a `BroadcastChannel` (`fuobe-generations`, messages event | state | hello). The next tab takes over when the leader closes; a tab hidden for 30 s lets go, and every reconnect after the first invalidates the caches. Without Web Locks each tab reads its own stream. State lives on `globalThis.__fuobeClientStream`; the decision logic (`streamResponse`, `needsCatchUp`, `toChannelMessage`) and the cache reducers are pure, in `src/lib/generation-stream.ts`. `applyEvent()` patches `["generations", filter]`, `["library", filter]`, `["assist", id]` and `["canvases", id]` (`applyToCanvasView`) by id, with id-based structural sharing (`shareById`). Other views subscribe with `useGenerationEvents(cb)` (Cinema, Layers, Shorts, Mixed Media, Marketing, Faceless, dub, Katana) instead of opening an EventSource. Polling slows to 10 s while connected (1.5 s otherwise); a 404 means no stream, retried every 5 minutes.

Notifications (round 4): `src/components/job-notifications.tsx`, with the decisions pure in `src/lib/job-watch.ts` and the per-browser opt-in in `src/lib/notification-prefs.ts` (Settings → Notifications). A job is a batch (a pipeline's steps count as one), and it counts as done only after it has stayed finished for 6 s, so steps a studio adds meanwhile belong to it. Only the stream's leader tab notifies, after asking the other tabs on the channel whether one is on screen. While notifications are on and a job hasn't had its notification yet, a hidden leader keeps its stream past the 30 s grace (`keepStreamWhileHidden`). The tab title counts running jobs ("(2) Library · Fuobe").

## Library: Trash, folders, pins, review, bulk, zip (`src/server/library.ts`)

- **Trash** is the `generation_trash` table (soft delete). Every reader (`listGenerations`, `getGeneration(id, {includeDeleted})`, and through them Assist, MCP, storyboards, studios) leaves trashed rows out; `toGeneration` fills `deletedAt` / `folderId` even for rows read without the join. `trashGenerations` cancels queued and running jobs; `restoreGenerations` brings rows back (to the root when their folder is gone). `deleteForever` / `emptyTrash` call `deleteGeneration`, which removes the row, its trash and folder entries and every output file that `assetInUse()` doesn't find in a table listed in `ASSET_REFS` (in `generations.ts`: generations, elements, trainings, Assist chats with their frozen context and project sources, Cinema, Canvas, Layers with its tools' inputs, Shorts, marketing, image studios, Faceless channels and episodes with their scripts and plans, dub sessions, Katana jobs, and since round 4 part 2 Content Factory series with their reference clip). Each entry also says what a row is and how to name it, so `assetUses()` can say where a file is used ("2 results and the element “Maya”"). `ASSET_FREE` lists columns that look like file columns but never hold one (round 4 part 2 adds `lora_mirrors`' source URL, hosted URL and licence: a LoRA's download and the provider's copy, never Fuobe's files); a test checks that every `_json`, `_url`, `url` and `_file` column is in one list or the other. When a table starts storing file URLs, add it there. `ensureTrashPurge()` empties what has been in the Trash for 30 days, at startup and then daily.
- **Folders**: `folders` + `folder_items`, one folder per generation. Since round 4 folders nest (`folders.parent_id`, up to `MAX_FOLDER_DEPTH` = 8 levels); names are unique among siblings, and a move into the folder itself or one of its subfolders is refused. Deleting a folder moves its results and subfolders up to its parent (to the root for a top-level folder). A folder's count and cover leave out the Trash and helper steps. `GET /api/folders/[id]/zip` zips a folder with its subfolders as paths (`?check=1` asks first, `?steps=1` adds helper steps).
- **Pins and review**: `pinned_at` on folders (pinned folders list first, in the order they were pinned) and on generations (`pinned=1` lists the most recently pinned first, with the cursor on the pin time; the Library shows them in a Pinned section) and `generations.review` (`in-progress`, `needs-review`, `approved`, `rejected`, or none), set through `PATCH /api/generations/[id]` (`pinned`, `review`) and the bulk route.
- **Helper steps**: a list that names no feature and no batch (the Library, the home feed, Assist's `list_recent`) leaves out chain steps (features ending in `-step`) and the helper features in `HELPER_FEATURES` (`src/lib/library.ts`; since round 4 part 2 also `eval`, the evaluation harness's jobs) unless `steps=1`; studio feeds that name their features still get them, and the facets count them apart.
- **Lists** take `kinds`, `models`, `statuses`, `since` / `until`, `folder` (or `folders`, a subtree), `trash`, `pinned`, `reviews`, `steps`, `q` (also the request prompt) and a compound cursor `before=<ts>:<id>` (ordered by ts DESC, id DESC; `deletedAt` in the Trash), so rows sharing a timestamp are never skipped. `libraryFacets()` gives the tab counts.
- **Bulk**: `POST /api/generations/bulk` (trash | restore | delete | favorite | unfavorite | move | pin | unpin | review), sent in batches of 500.
- **Zip**: `GET /api/generations/zip?ids=` streams a stored zip (`zipStream` / `zipSize` in `src/server/zip.ts`: a CRC pass first, flat memory, refused over 4 GB). `zipToFile` writes one to disk from files that arrive one at a time (EXR frames).
- **Uploads**: `DELETE /api/assets/[id]` deletes a stored file for good, its file on disk included, only when nothing uses it (`deleteUnusedAsset`); otherwise it answers 409 with where it is used. `GET` returns the uses.
- Client: pure helpers in `src/lib/library.ts` (filters, date sections, batch stacks, `cursorAfter`, `toggleAll` for Select all and per-day select, `describeUses`), `outputActions()` in `src/lib/output-actions.ts` (one action list for tiles, viewer and Library), `ForeverConfirmProvider` in `src/components/studio/result-actions.tsx`, and `components/library/{folders,review,upload-delete}.tsx` (folder tree with breadcrumbs and drag-and-drop, the review picker, the checked upload delete). `GenerationRequest.title` / `.batchTitle` (server-set) name results and Library stacks.

## Security (`src/proxy.ts`, `src/server/auth.ts`, `src/server/remote-fetch.ts`)

- **Sign-in** is off until a password is set in Settings → Security or `FUOBE_PASSWORD`. State lives in `data/auth.json` (not SQLite) so the proxy can check requests with `fs` and `crypto` alone: a scrypt password hash, an HMAC secret for 30-day session cookies (replaced when the password changes), and API tokens stored as SHA-256 hashes. The proxy lets `/login` and `/api/auth/login` through, answers other API calls with 401 and redirects pages to `/login?next=…` (`safeNext()` in `src/lib/safe-redirect.ts` keeps it on the same origin). Its matcher leaves out only build assets, `samples/` and root SVGs.
- **Host allowlist** (`hostAllowed`), for every method when no password is set, before anything else: IP literals, localhost and `*.localhost`, single-label names, `.local` / `.lan` / `.home.arpa` / `.internal` / `.localdomain`, this machine's hostname, and `FUOBE_ALLOWED_ORIGINS` (`*` allows any). This stops DNS rebinding. `X-Forwarded-Host` is not trusted here.
- **Cross-site writes** (`crossSite`): non-GET/HEAD/OPTIONS requests get 403 when `Origin` matches neither Host, `X-Forwarded-Host` nor `FUOBE_ALLOWED_ORIGINS`, when it is `null`, or when `Sec-Fetch-Site` is cross-site — with or without a password.
- **Login throttle** (`LoginGuard`): 5 misses per client and 20 a minute overall, bounded map, `Retry-After`. Route handlers can't see the socket address, so the client key is the last `X-Forwarded-For` hop only with `FUOBE_TRUST_PROXY=1` (then a 60 s lock per client); otherwise everyone shares a key that is slowed to one attempt every 4 s and never locked.
- **Remote fetch** (`fetchRemote`): every caller-supplied URL (references, brand research, product links, YouTube oEmbed, Assist sources) is fetched only from public addresses. The check runs inside the socket lookup (DNS can't change after it) and again on each of at most 5 redirects; it blocks loopback, RFC 1918, link-local / metadata, CGNAT, multicast, ULA and mapped / NAT64 / 6to4 IPv4. 60 s deadline, 200 MB cap. `fetchRemoteToFile` makes the same checks but streams to a file (16 GB cap, 30-minute deadline; a failed download leaves no file); it fetches the extra files a result links to. `FUOBE_ALLOW_PRIVATE_URLS=1` turns both off for LAN installs.
- **LoRA links** (round 4 part 2) don't go through `fetchRemote`. `POST /api/generations` takes a LoRA link only over https on huggingface.co, hf.co, civitai.com, fal.media or replicate.delivery, with no credentials in it (`LORA_HOSTS` in `src/app/api/generations/route.ts`), and a file name that stays inside the LoRA folder (`lorasPath` also requires `.safetensors`). The server may download such a file into the LoRA folder before a ComfyUI run. Downloads from huggingface.co and civitai must match a SHA256; a link on hf.co, fal.media or replicate.delivery isn't held to one, so such a file can be kept unchecked, with no size limit and a 60-minute timeout. The civitai key travels only in civitai's download URL and is redacted from messages.
- **Connection tests** (`POST /api/providers/test`, `src/lib/connections.ts`): Settings' Save & test sends the typed, unsaved values; the route runs the provider's `test()` inside `withCandidates()` (an `AsyncLocalStorage` override of `getSetting`, `src/server/settings.ts`) and stores nothing. Testing a different, unsaved ComfyUI address doesn't send the saved token to it (`isCandidate` / `savedSetting`). Like saving an address, a test makes the server fetch the ComfyUI or Ollama address it is given. Since round 4 part 2 the route also tests the civitai key (`{provider: "civitai"}`, civitai's `/me`), which isn't a model provider's.
- Uploads up to 200 MB pass the proxy (`experimental.proxyClientMaxBodySize: "210mb"` in `next.config.ts`, room for the multipart overhead). `/api/files` sends `nosniff` and a UTF-8 charset for text. The MCP endpoint refuses a foreign `Origin`. **Real 404s**: the proxy rewrites an unknown `/apps/<id>`, an unknown hub mode (`unknownHubMode`) and a record page whose id isn't stored (`recordForPath` in `src/lib/record-pages.ts`, then `recordExists` in `src/server/records.ts`, one primary-key lookup; a database that can't be read counts as "exists") to the not-found page with a 404, because a page's `loading.tsx` streams a 200 before the page knows. Every `[id]` page also calls `notFound()`.

## Training (`src/server/training.ts`)

A `trainings` row per job, polled by the same runner. Higgsfield Soul ID returns a reference id stored on the element; fal's Z-Image trainer gets a zipped dataset with captions and returns a LoRA URL; AI-Toolkit gets a dataset folder and a job through its UI's job API, and the finished LoRA is copied into `COMFYUI_LORAS_DIR` (since round 4 part 2 also the folder recipe LoRAs are downloaded into; see LoRAs). A style element (moodboards) uses the style preset (`aiToolkitJob({ kind: "style" })`, captions "<trigger> style", 1500 steps). Failed fal jobs (4xx, `FAILED`), a missing AI-Toolkit job, 8 h without a result and uploads cut off by a restart fail the training and settle the element back to ready.

## Assist agent (`src/server/assist/`)

A manual tool-use loop over Claude (adaptive thinking with `block_binding` drop-block, betas `thinking-binding-controls-2026-08-01` and `server-side-fallback-2026-07-01` (not for Haiku), top-level `cache_control` and two cached system blocks, streamed with `client.beta.messages.stream(...).finalMessage()`, `max_tokens` 32k or 64k at Extra / Max effort). Modes: **Free** (Ollama, or the offline planner), **Smart** (Claude, needs a key), **Manual** (pick claude-opus-5-5, claude-sonnet-5-5, claude-haiku-5-5 or claude-fable-5-1 and the effort). `resolveAgent()` picks one per chat.

- **Context.** Each chat's context (date, engine, approval mode, project, sources, memory, skills index, active skills) is built once and frozen in `assist_thread_state`; later changes arrive as role `system` "Context update" messages, saved only after a reply succeeds, so preserved thinking stays valid.
- **Tools** (`tools.ts`, `context-tools.ts`, `studio-tools.ts`): `search_models` (kinds image, video, audio, text, model3d), `list_elements`, `list_recent`, `check_generations` (text inline, meta, images attached), `generate` (with `after`: the call becomes one `createPipeline`; not `strict`, zod-validated), `create_storyboard` (the only `strict` tool), `list_skills`, `load_skill`, `remember` (asks first), `read_source`, the studio tools `split_layers`, `restyle_footage`, `dub_video`, `faceless_episode`, `create_ads`, `add_captions`, and `katana`. Gated calls stop the loop with an approval card priced by `previewGeneration`; `PlannedJob.atomic` marks a pipeline's steps and `planRunnable()` keeps Run off while any step has an error. `answerApproval` claims the thread before its first await.
- **Studio tools** resolve through `STUDIO_ROUTES`, which `assist/studio-routes.ts` fills (since round 4) for `split_layers`, `restyle_footage`, `dub_video`, `faceless_episode`, `create_ads` and `add_captions`. Each adapter prices the job with the studio's own estimate and starts it through the studio's server module, so it opens as a Layers project, a Shorts session, a dub to review, a Faceless episode (in an "Assist" channel made once) or an Ads Studio batch, or in the Captions editor. A call the studio can't take runs as a `createPipeline` of catalog models in the Library, and the card, the result and the chat say why. `planFor()` returns where the job opens (`JobPlace`: studio and page), for the approval card and MCP's `estimate_job`. Genjutsu, Remove object, Content Factory, the AI Influencer builder and Layers' Inpaint, Enhancer and Save as element have no Assist or MCP tool yet.
- History is stored append-only exactly as the API returned it; local images are kept as URLs and converted to base64 per request. The same loop runs on Ollama's tool calling, or with no LLM on a rule-based planner (still → animate, N-shot films, N takes numbered on their tiles and then "animate 2" for the one picked, translations, skill hints, "remember that…").

## MCP server (`src/server/mcp.ts`, `/api/mcp`)

Fuobe's MCP server (version 1.2.0; protocol revisions 2025-11-25, 2025-06-18, 2025-03-26 and 2024-11-05) over streamable HTTP, stateless with JSON responses: `initialize`, `ping`, `tools/list`, `tools/call`, `resources/list` (empty), `prompts/list`, `prompts/get`. The tools are Assist's (shared `executeTool`) with read-only hints, plus `estimate_cost` (a generate call priced with `previewGeneration`) and `estimate_job` (a studio tool's plan, with the studio and page it opens in). A studio tool's result carries its job's `href` on this server. `mcp.ts` imports `assist/studio-routes.ts` itself, so the studio adapters are always loaded. The prompts are the enabled skills. Requests from a foreign `Origin` are refused; the proxy applies the same sign-in rules as the REST API. Content Factory's Generate in Claude (round 4 part 2) sends nothing itself: its dialog shows the `claude mcp add --transport http fuobe <origin>/api/mcp` line (`mcpCommand`, with a Bearer header when a password is set) and the prompt `POST /api/content-factory/claude` writes for the existing `faceless_episode` tool, on the engine this server's MCP runs on (Settings → Engine mode). That tool takes up to 8 scenes a call, so a longer episode comes out in parts.

## Command line (`bin/`)

`fuobe` (round 4) is a client of a Fuobe server, not part of it: plain Node 20+ with no dependencies, `bin/fuobe.mjs` (the `bin` entry in `package.json`) with the logic in `bin/lib/*.mjs` so tests drive it without a terminal. It finds the server and token in `--url` / `--token`, then `FUOBE_URL` / `FUOBE_TOKEN`, then the file `fuobe login` saves (`~/.config/fuobe/config.json`, written 0600; the saved token goes only to the server it was saved for). It uses the same REST API as the browser: `GET /api/models` (`src/app/api/models/route.ts` with `src/lib/model-list.ts`: what this install can run, with `runs` real / demo / refused worked out as `chooseRoute` would, and the studios' default picks), `POST /api/generations` and its `?preview=1` (model, operation, jobs, outputs and cost, nothing created), `POST /api/uploads`, `GET /api/generations[/<id>]`, the Assist skills routes, and `POST /api/mcp` for the studio tools (`fuobe tool`). Skills follow the Agent Skills format, so other agents can install them (`.agents/skills/fuobe` teaches one to drive Fuobe through MCP or the CLI). Since round 4 part 2, `fuobe eval <command>` is a `passthrough` command (it takes its arguments as they are): it imports the evaluation harness (`scripts/eval/eval.mjs`) from the checkout next to the CLI and refuses to run without one; the harness finds its server and token the same way, so a saved token still goes only to the server it was saved for. Commands, options and exit codes: [`docs/cli.md`](cli.md).

## Evaluation harness (`scripts/eval/`)

Round 4 part 2. A developer tool, not part of the app: it measures the Fuobe Originals (Fuobe's own open-weight versions of Higgsfield's in-house models) so that a recipe (models, LoRAs, settings) becomes a default only after it has been measured, and then only in a commit a person reviews. Like the CLI it is a client of a running Fuobe, in plain Node: `scripts/eval/eval.mjs` (`run`, `report`, `review`, `compare`, `promote`, `covers`, `history`, `validate`, `setup`, `trash`; `pnpm eval:<command>` or `fuobe eval <command>`) with the logic in `scripts/eval/lib/*.mjs`. The full guide is [`scripts/eval/README.md`](../scripts/eval/README.md).

- **Cases** (`cases/*.json`, checked against `case.schema.json`, which `lib/schema.mjs` writes): one suite per Original (`selftest`, `soul`, `soul-id`, `dop`, `genjutsu`, `mixed-media`, `shorts`, `speak`, `cinema`) with model targets per engine (`demo`, `open`, `cloud`), variants (`recipe`, `prompt-only`, `half-strength`, a cloud `partner`…) and inputs from `local/` (git-ignored: photos, clips, voices) or the small synthetic `fixtures/` for demo runs. `soul.json` and `dop.json` are generated by `gen-cases.mjs` from `higgsfield-image-studios.json` (look ids) and `fuobe-originals-recipes-5.json` (recipes, LoRAs, the motion map); `eval:validate` fails when they're out of date.
- **Runner** (`lib/run.mjs`, `plan.mjs`, `recipes.mjs`): every job goes through Fuobe's REST API (`/api/generations` with the recipe's `loras`, `/api/uploads`, `/api/elements`, and studio routes such as `/api/genjutsu` and `/api/mixed-media`) with the feature `eval`, a helper the Library hides. The harness holds no prices: each job is priced by the server's preview or estimate, a cloud job reserves its price under the spend cap (`--max-usd`, default $5), and an unpriced one is skipped unless `--allow-unpriced`. A job whose route (the preview's `route`) or studio estimate (`providers`) goes through Higgsfield's API is skipped. On the open engine it also reads ComfyUI, read-only (`/system_stats`, `/history`, `/object_info/LoraLoader`). Each run is a folder under the git-ignored `scripts/eval/results/` (`run.json`, `jobs.jsonl`, the outputs, `metrics.json`, `summary.json`, `report.html`).
- **Metrics** (`metrics/fuobe_metrics`, Python) run in their own venv, which `pnpm eval:setup` makes with uv from pinned requirements (CPU torch by default); `lib/metrics.mjs` starts `python -m fuobe_metrics.score` from that venv, else through `uv run`. CLIP score, the LAION aesthetic predictor, style against reference images (CLIP or DINOv2), identity (AuraFace with the YuNet face detector, installed with `--identity`), temporal drift and warp error, a lip-sync proxy and shot continuity; every weight is pinned to a Hugging Face revision and its licence is stored with the scores. Without Python, a run keeps its timing and cost.
- **Report, review, compare, promote** (`report.mjs`, `review.mjs`, `compare.mjs`, `covers.mjs`): a contact sheet; a blind A/B page served on 127.0.0.1:4173 (ratings saved next to the run; the key to which side is which is never served); `compare` exits 1 when a guarded metric regresses; `promote` applies the promote rule (licence, at least 3 results, metrics against every alternative, and at least 6 blind ratings of the case's pairs, or every pair when the review offered fewer, with 55 % of the non-tie ones for the candidate) and with `--record` writes its verdicts into `fuobe-originals-recipes-5.json` (`--apply-strengths` also lowers over-cooked LoRA strengths) as a diff to review; `covers` turns promoted renders into preset covers listed in `src/lib/preset-previews.generated.ts`, which `previewFor` shows instead of the procedural preview.
- **Server seams** it relies on: `loras` on `POST /api/generations`, the preview's `route`, `prompt` and `loras {applied, dropped}` (`routeLoras`), and `providers` on the Genjutsu and Mixed Media estimates.

Checked: the self-test ran on a CPU ComfyUI and scored 4 CPU-only jobs, demo runs pass, and the report and review pages are browser-tested (`tests/e2e/eval-review.mjs`). No Original has been measured on a GPU or the cloud, no recipe has been promoted, and `preset-previews.generated.ts` is still empty.
